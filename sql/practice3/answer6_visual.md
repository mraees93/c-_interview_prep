# 🚫 Visual Breakdown: The Dual-Join Exclusion Trick

### The Query
```sql
SELECT DISTINCT 
    c.CandidateID, 
    c.FullName
FROM Candidates c
JOIN Verifications p ON c.CandidateID = p.CandidateID AND p.Status = 'Pending'
LEFT JOIN Verifications f ON c.CandidateID = f.CandidateID AND f.Status = 'Flagged'
WHERE f.CandidateID IS NULL;
```

---

### Step 0: Raw Mock Tables

**Candidates Table (`c`)**
*Contains your core applicant roster.*

| CandidateID | FullName |
| :--- | :--- |
| **1** | John Doe |
| **2** | Jane Smith |
| **3** | Bob Johnson |

**Verifications Table**
*Contains the full verification history. Notice Jane has multiple rows with conflicting statuses.*

| CheckID | CandidateID | Status |
| :--- | :--- | :--- |
| 101 | 1 | Pending |
| 102 | 2 | Pending |
| 103 | 2 | Flagged |
| 104 | 3 | Complete |

---

### Step 1: The Inner Join (`JOIN ... AND p.Status = 'Pending'`)
The engine matches candidates to their **'Pending'** rows. 
* **John (ID 1)** and **Jane (ID 2)** both have a pending row, so they pass.
* **Bob (ID 3)** has no pending records, so he is **dropped immediately** from the entire process.

**Intermediate Result 1:**
*Bob is gone. Only candidates with at least one pending check remain.*

| c.CandidateID | c.FullName | p.Status |
| :--- | :--- | :--- |
| **1** | John Doe | Pending |
| **2** | Jane Smith | Pending |

---

### Step 2: The Left Join (`LEFT JOIN ... AND f.Status = 'Flagged'`)
The engine looks back at the `Verifications` table a second time, searching **only** for records that match our remaining candidates **and** have a 'Flagged' status.

* **John (ID 1):** Has no flagged records. The engine is forced to keep John because it's a `LEFT JOIN`, so it fills all incoming `f` columns with **`NULL`**.
* **Jane (ID 2):** Has a flagged record. The engine successfully hooks the data up.

**Intermediate Result 2:**
*The 'f' table fields act as a trap to catch flagged individuals.*

| c.CandidateID | c.FullName | p.Status | f.CandidateID | f.Status |
| :--- | :--- | :--- | :--- | :--- |
| **1** | John Doe | Pending | <span style="color:red">**NULL**</span> | <span style="color:red">**NULL**</span> |
| **2** | Jane Smith | Pending | **2** | **Flagged** |

---

### Step 3: The Where Clause Filter (`WHERE f.CandidateID IS NULL`)
The engine scans the **`f.CandidateID`** column generated by the step 2 lookup and executes the exclusion check.

| Row Profile | f.CandidateID Tracking Value | Filter Decision |
| :--- | :--- | :--- |
| **John Doe** | <span style="color:red">**NULL**</span> (No flagged records found) | **KEEP** (It matches IS NULL) |
| **Jane Smith** | **2** (A flagged record connected successfully) | **DROP** (It fails IS NULL) |

---

### Final Output (`SELECT DISTINCT`)
The engine drops the background testing columns and strips out any remaining duplicate rows, outputting your clean candidate list.

| CandidateID | FullName |
| :--- | :--- |
| **1** | John Doe |
