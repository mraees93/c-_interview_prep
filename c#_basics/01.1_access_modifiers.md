# Access Modifiers, Fields, and Methods Cheat Sheet

## 1. Core Definitions & Analogies

### Public (`public`)
*   **Definition:** The member or type is fully accessible from **anywhere** inside the application, including other files, folders, and external assemblies/projects.
*   **Analogy:** A **public vending machine** in a mall lobby. Anyone walking past can see it, touch it, press its buttons, and interact with it directly.

### Private (`private`)
*   **Definition:** The member is accessible **only** within the boundaries of the specific class or struct where it is declared. It is completely invisible to outside classes. (This is the default C# modifier if you leave it blank).
*   **Analogy:** Your **smartphone passcode**. It is a crucial part of your daily process, but only you can interact with it internally; the public outside world has no direct access to it.

### Static (`static`)
*   **Definition:** `static` is a life-cycle modifier, not an access modifier. It dictates **how memory is stored**. A static member belongs to the **class itself** as a single global entity, rather than belonging to individual object instances created via the `new` keyword.
*   **Analogy:** A **classroom whiteboard**. There is exactly one whiteboard for the entire room. Every student (instance) looks at the exact same board. If one student walks up and writes on it, the data changes globally for everyone else in that room instantly.

---

## 2. Structural Components Explained

### Fields
*   Variables declared directly inside a class to hold raw structural data. They should almost always be kept `private` to maintain data safety (**Encapsulation**).

### Methods
*   Code blocks containing executable instructions. They perform actions, run calculations, and can accept inputs and return outputs.

---

## 3. Basic Component Snippets

### Class Members Setup
```csharp
public class BankAccount
{
    // PRIVATE FIELD: Hidden from the outside world to protect the data state
    private decimal _balance;

    // PUBLIC METHOD: Exposed to everyone so they can safely interact with the account
    public void Deposit(decimal amount)
    {
        if (amount > 0)
        {
            _balance += amount; // Allowed: Internal code can modify private fields
            LogTransaction(\$"Deposited: {amount}");
        }
    }

    // PRIVATE METHOD: Only used internally for internal algorithmic housekeeping
    private void LogTransaction(string message)
    {
        Console.WriteLine(\$"[LOG]: {message}");
    }
}
```

### Static vs Instance Evaluation
```csharp
public class FleetCar
{
    // INSTANCE FIELD: Every separate car object tracks its own unique color state
    public string Color { get; set; } = "White";

    // STATIC FIELD: There is only ONE counter in memory shared across ALL cars globally
    public static int TotalCarsCreated { get; private set; }

    public FleetCar()
    {
        TotalCarsCreated++; // Increments the single global shared counter
    }
}

// --- Practical Application Execution ---
FleetCar car1 = new FleetCar { Color = "Red" };
FleetCar car2 = new FleetCar { Color = "Midnight Blue" };

Console.WriteLine(car1.Color); // Output: Red
Console.WriteLine(car2.Color); // Output: Midnight Blue

// Notice you call static variables directly on the Class name, not the object!
Console.WriteLine(FleetCar.TotalCarsCreated); // Output: 2
```

## 4. Static Classes
*   Marking an entire class as `static` prevents anyone from creating an object instance out of it using the `new` keyword.
*   It serves purely as a stateless container for utility calculations and global helper functions.
*   **Strict Rule:** Every single field, property, or method declared inside a static class **must** also be explicitly marked as `static`.

```csharp
public static class MetricConverter
{
    public const double KmToMilesMultiplier = 0.621371;

    public static double KilometersToMiles(double kilometers)
    {
        return kilometers * KmToMilesMultiplier;
    }
}

// --- Practical Application Execution ---
// No "new MetricConverter()" is allowed! Call it directly:
double miles = MetricConverter.KilometersToMiles(100); 
```

## 5. Common Combinations Matrix

| Combination Keyword Set | Applicable Targets | Architectural Meaning | Typical Real-World Use Case |
| :--- | :--- | :--- | :--- |
| **`public static`** | Methods, Fields, Properties | Global access entry point. Executable from anywhere instantly without generating an instance object. | Mathematical utility helpers, project-wide constant parameters, configurations. |
| **`private static`** | Methods, Fields | Shared across instances globally in memory, but completely locked away from external files. | Internal cache memory pools, runtime diagnostic trackers, internal singletons. |
| **`public`** (Instance) | Methods, Properties | Globally accessible, but requires you to initialize a unique object via `new` first. | Domain models, API endpoint structures, service dependency interfaces. |
| **`private`** (Instance) | Fields, Methods | Locked inside the runtime object instance lifecycle. Invisible to the external application layers. | Database backing fields, local step-by-step algorithms, processing flags. |

## 7. Advanced Access Modifiers (Inheritance & Assembly Scoping)

### Protected (`protected`)
*   **Definition:** The member is accessible only within its own class and by **derived (child) classes** that inherit from it. It remains completely hidden from outside unrelated classes.
*   **Analogy:** A **family heirloom**. It is passed down through generations within the family line (inheritance), but neighbors or random people on the street cannot access it.

### Internal (`internal`)
*   **Definition:** The member or class is accessible from **anywhere within the same project/assembly** (the compiled `.dll` or `.exe`), but completely hidden from external projects or packages referencing it.
*   **Analogy:** A **company intranet**. Any employee working inside the building can log in and view the documents, but the general public outside the organization cannot access it.

### Protected Internal (`protected internal`)
*   **Definition:** A combination modifier. Accessible from anywhere within the same project, **OR** by any child class in an entirely different project via inheritance.

### Private Protected (`private protected`)
*   **Definition:** The strictest combination modifier. Accessible only by child classes, and **only** if those child classes live inside the exact same project/assembly.

## 8. Advanced Component Snippets

### Protected Inheritance Example
```csharp
public class Vehicle
{
    // PROTECTED FIELD: Child classes can use this, but external objects cannot
    protected string EngineType = "V6";
}

public class RacingCar : Vehicle
{
    public void DisplayEngine()
    {
        // Allowed because RacingCar inherits from Vehicle
        Console.WriteLine(\$"This race car has a {EngineType} engine.");
    }
}

public class House
{
    public void CheckCar()
    {
        Vehicle myCar = new Vehicle();
        // ❌ COMPILER ERROR: EngineType is protected and House does not inherit from Vehicle
        // string type = myCar.EngineType; 
    }
}
```

### Internal Project Scoping Example
```csharp
// Project A (Core Library System)
internal class InternalDatabaseTokenGenerator
{
    // Accessible anywhere inside Project A
    public string GenerateToken() => "SecretToken123";
}

// Project B (External UI Framework referencing Project A)
public class DashboardView
{
    public void Initialize()
    {
        // ❌ COMPILER ERROR: InternalDatabaseTokenGenerator cannot be accessed 
        // because it is internal to Project A.
        // var generator = new InternalDatabaseTokenGenerator(); 
    }
}
```

## 9. Expanded Combinations Matrix

| Combination Keyword Set | Applicable Targets | Architectural Meaning | Typical Real-World Use Case |
| :--- | :--- | :--- | :--- |
| **`protected`** | Methods, Fields, Properties | Hidden from the public, but visible to inheriting child subclasses. | Base class structural settings, internal abstract framework overrides. |
| **`internal`** | Classes, Methods, Fields | Public to your immediate project assembly, but private to external consumers. | Service implementations you want to hide from public NuGet package users. |
| **`protected internal`** | Methods, Fields, Properties | Visible anywhere in the same project, plus child classes across different projects. | Framework API extensibility hooks for multi-project architecture setups. |
| **`private protected`** | Methods, Fields, Properties | Restricted tightly to child classes located inside the same project boundary. | Internal class library micro-optimizations across family classes. |

## 10. Cheat Sheet Advanced Combination Code Snippets

### A. Protected Method Snippet
```csharp
public class BaseRepository
{
    // Child repositories can run this query tool, but controllers cannot call it directly
    protected string BuildConnectionString()
    {
        return "Server=myServerAddress;Database=myDataBase;";
    }
}

public class UserRepository : BaseRepository
{
    public void GetUser()
    {
        string conn = BuildConnectionString(); // Allowed via inheritance
    }
}
```
